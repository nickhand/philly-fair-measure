# Fair Measure, public dashboard

The Vue 3 + TypeScript front end for the Fair Measure assessment check, live
at [nickhand.dev/fair-measure](https://nickhand.dev/fair-measure/). It renders
the citywide map (MapLibre), the address search, and the per-property report
against the FastAPI backend in `src/philly_fair_measure/api.py`. Architecture
and deployment notes are in [docs/frontend.md](../docs/frontend.md).

## Development

```sh
npm install
npm run dev          # dev server on :5173, proxies /api to :8000
```

Start the API alongside it from the repository root:

```sh
uv run fair-measure api    # JSON API on :8000
```

## Checks

```sh
npm run test:unit    # Vitest
npm run type-check   # vue-tsc
npm run lint         # ESLint
npm run build        # type-check + pre-render + generated-HTML checks
```

## Configuration

| Variable | Purpose | Default |
|---|---|---|
| `VITE_API_BASE` | Absolute base URL for API requests | empty (same-origin `/api`, proxied in dev) |
| `VITE_PUBLIC_BASE` | Base path the site is served under | `/` (production uses `/fair-measure/`) |
| `VITE_ANALYTICS_ENABLED` | Explicitly enable analytics in a production-mode build | enabled unless set to `false` |

Production values and routes live in `wrangler.jsonc`. Use
`npm run deploy:cloudflare:staging` for the noindex canary and
`npm run dry-run:cloudflare:production` to validate the canonical configuration
without publishing it. Only the protected GitHub Actions environment may mutate
the `www.nickhand.dev/fair-measure/*` production Worker. Main-branch web changes
are released automatically from the validated artifact, with the original
Cloudflare Worker version retained for rollback. Site-wide links and the
displayed assessment year are in `src/config/site.ts`. Displayed statistics come from
`src/data/siteStats.json`, which is committed and regenerated by
`uv run fair-measure export-web-stats` after each model run.

## Pre-rendering

Vite SSG builds HTML for Home, Findings, the annual report (including `/report`),
Methodology, Trust, and Appeal. Routes opt in through `meta.prerender` in
`src/router/index.ts`. Unhead writes route-specific titles, descriptions,
canonical URLs, and social metadata at build time and keeps them current during
browser navigation. No API connection is required to build: Home starts with
the committed screen counts and refreshes them in the browser.

Map, admin, and property-report URLs use `dist/spa.html`, an empty app shell,
and render in the browser. Generated pages hydrate their existing HTML; the
fallback and Vite dev server mount normally. The Cloudflare Worker resolves
clean URLs to generated `.html` files, redirects trailing slashes within the
public base path, and falls back only to the separate SPA shell. Unknown URLs
return 404, and admin routes remain noindex. `npm run preview` also uses the
separate shell for routes without generated HTML.

Appeal deadlines are rendered with date-neutral wording. The banner and
past/current deadline status activate after mounting in Philadelphia time, so
an older build cannot freeze a deadline as still open or cause a hydration
mismatch. Account query parameters are also applied after mounting.

Every build runs `scripts/check-prerender-output.mjs`, checking substantive
HTML, metadata uniqueness, canonical URLs, date-neutral copy, and the fallback.
`npm run test:worker` covers production route resolution; unit tests cover
hydration across deadlines and account-prefilled links.
